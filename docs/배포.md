# 서버 배포 (EC2 t4g.small)

> 2026-10-22. 개인 실험 저장소에서 EC2 t4g.small로 실제 올려 보고 시험한 구성이다. 구성 파일은 `deploy/`, 올리는 스크립트는 `scripts/deploy.py`.
> 팀 서버는 아직 정하지 않았다(설계 D6 — 학교 클라우드 4GB급 / Lightsail / EC2). 어느 쪽이든 Docker가 도는 Ubuntu면 3장 · 4장은 그대로 쓴다. 2GB면 6장 메모리 설정이 필요하다.

## 1. 구성과 원칙

```
브라우저 ──HTTPS──▶ Caddy (80 · 443, 인증서 자동, 비밀번호)
                     ├─ /api/*  ──▶ FastAPI (uvicorn 1 워커)  ──▶ Neo4j (포트 안 엶)
                     └─ 그 밖    ──▶ frontend/out (정적 화면)
```

- **서버는 보여 주기만 한다.** 수집 · 적재 · 검수는 지금처럼 PC에서 하고, 서버에는 코드 · 화면 · DB 덤프만 올린다.
  - 2GB에서 ETL을 돌리면 pandas가 메모리를 넘길 수 있다(HANDOFF 5장).
  - 서버 DB는 PC 덤프로 통째로 바뀌므로, 서버에서 검수하면 그 검수는 사라진다. 그래서 Caddy가 `/admin` · `/api/v1/admin`을 404로 막고, API에도 `ADMIN_TOKENS`를 건다.
  - 재생 불가 신고(API-12)도 서버 DB에 남지만, 다음에 덮어쓸 때 사라진다.
- **기본은 비밀번호로 잠근다** (`ACCESS=private`). 시연 전까지는 팀원만 보게 둔다. 누구나 보게 하려면 `ACCESS=public`.
- 프로젝트 이름은 `baseon-server` — 로컬 개발 환경(`baseon`)과 볼륨이 겹치지 않는다.

## 2. EC2 만들기 (AWS 콘솔, 처음 한 번)

| 항목 | 값 |
| --- | --- |
| 리전 | 아시아 태평양(서울) `ap-northeast-2` |
| AMI | Ubuntu Server 24.04 또는 26.04 LTS, **64비트(Arm)** (시험 서버는 26.04.1) |
| 인스턴스 유형 | **t4g.small** (2 vCPU · 2GB) |
| 키 페어 | 새로 만들기 → `baseon.pem`을 `C:/Users/<나>/.ssh/`에 |
| 보안 그룹 | SSH 22 · HTTP 80 · HTTPS 443 = 어디서나 (아래) |
| 스토리지 | 20GB gp3 |
| 고급 세부 정보 → **크레딧 사양** | **표준(Standard)** — 기본 「무제한」이면 CPU를 오래 쓸 때 초과 크레딧이 요금으로 나온다 |

- **SSH를 어디서나 여는 이유**: 「내 IP만」이면 집 IP가 바뀌거나 다른 네트워크에서 배포할 때 막힌다. 그 대신 `server_setup.sh`가 키로만 들어오게(비밀번호 · root 로그인 끔, 시도 3번) 하고, 여러 번 틀린 IP는 fail2ban이 막고, 보안 업데이트는 unattended-upgrades가 자동으로 한다. `baseon.pem`은 나눠 주지 않는다 — 다른 사람이 필요하면 각자 키를 만들어 서버 `~/.ssh/authorized_keys`에 더한다.
- 만든 뒤 **탄력적 IP**를 하나 받아 인스턴스에 붙인다(끄고 켜도 주소가 안 바뀐다).
- **결제 → Budgets**에서 월 $1 예산 알림을 만든다. 무료 범위를 넘으면 메일이 온다.

**비용** (AWS EC2 FAQ, 2026-10-22 확인)

| 항목 | 요금 |
| --- | --- |
| t4g.small 인스턴스 | **2026-12-31(UTC)까지 무료** — 모든 계정, 한 달 750시간, 서울 포함. 2027-01-01부터 일반 요금 |
| EBS 20GB | 체험에 포함되지 않음. 프리 티어(가입 12개월 · 새 무료 플랜) 계정이면 30GB까지 무료, 아니면 한 달 약 $2 |
| 공인 IPv4(탄력적 IP) | 체험에 포함되지 않음. 프리 티어 계정이면 750시간 무료, 아니면 시간당 $0.005(한 달 약 $3.6) |
| 초과 CPU 크레딧 | 크레딧 사양을 「표준」으로 두면 생기지 않는다 |

2027년부터 계속 쓸지는 12월에 정한다.

## 3. 도메인

HTTPS 인증서(Let's Encrypt)에는 도메인이 필요하다(유튜브 임베드도 HTTPS 도메인에서 확인 — HANDOFF 5장 오류 153).
가진 도메인이 없으면 [DuckDNS](https://www.duckdns.org)에서 `<이름>.duckdns.org`를 무료로 받아 탄력적 IP를 넣는다.

- 무료 도메인은 **「IP 연결」(A 레코드)**로 — URL 포워딩이면 인증서를 받을 수 없다.
- **Let's Encrypt는 상위 도메인마다 주 50개**까지만 낸다. 여럿이 나눠 쓰는 `kro.kr`(내도메인.한국)은 이 한도가 늘 차 있다(10-23 실제로 429). duckdns.org는 공개 접미사 목록에 있어 하위 주소마다 따로 센다.
  그래서 `deploy/.env`의 `ACME_EMAIL`을 꼭 넣는다 — 이메일이 있어야 Caddy가 Let's Encrypt가 막힐 때 **ZeroSSL**로 넘어간다.

## 4. 처음 배포

PC `.env`(저장소 맨 위)에 더한다:
```
DEPLOY_HOST=ubuntu@<탄력적 IP 또는 도메인>
DEPLOY_KEY=C:/Users/<나>/.ssh/baseon.pem
```

```bash
python scripts/deploy.py setup     # 스왑 2GB · Docker · /opt/baseon (deploy/server_setup.sh)
python scripts/deploy.py code      # 첫 실행은 「deploy/.env가 없다」로 멈춘다 → 아래
```

서버에서 `deploy/.env`를 만든다 (`deploy/.env.example` 참고, 이 파일은 서버에만 있다):
```bash
ssh -i C:/Users/<나>/.ssh/baseon.pem ubuntu@<서버>
cp /opt/baseon/app/deploy/.env.example /opt/baseon/app/deploy/.env
docker run --rm caddy:2.10.2-alpine caddy hash-password --plaintext '<화면 비밀번호>'   # → BASIC_AUTH_HASH
nano /opt/baseon/app/deploy/.env    # NEO4J_PASSWORD · SITE_ADDRESS(도메인) · ACME_EMAIL · BASIC_AUTH_USER · BASIC_AUTH_HASH · ADMIN_TOKENS
```

다시 PC에서:
```bash
python scripts/deploy.py code      # 화면 빌드 → 코드 · 화면 올리기 → 빌드 · 켜기 (Caddy가 인증서를 받는다)
python scripts/deploy.py db        # PC Neo4j를 1분쯤 멈추고 덤프 → 서버 DB를 바꾼다
python scripts/deploy.py status    # 컨테이너 · 메모리 · 디스크 · /meta
```

## 5. 그 뒤

- **코드 · 화면을 바꿨을 때**: 커밋 → `python scripts/deploy.py code`. `git archive HEAD`라 커밋하지 않은 변경은 올라가지 않는다.
- **DB를 바꿨을 때**(다시 적재 · 검수): `python scripts/deploy.py db`. 덤프는 PC `data/deploy/neo4j.dump`에 남는다.
- 되돌리기: 서버 `app.old/`에 바로 전 코드가 있다. DB는 따로 보관한 덤프를 `deploy.py db --dump <파일>`로.

## 6. 시험 (2026-10-22, PC에서 `--local`)

`python scripts/deploy.py code|db --local <폴더>`는 서버 대신 PC 폴더에 똑같이 올린다(프로젝트 `baseon-deploytest`, http://localhost:8080). 서버와 다른 점은 CPU가 amd64라는 것뿐이다(이미지 세 개 모두 arm64 있음).

| 확인 | 결과 |
| --- | --- |
| `code` | 빌드 · 묶음 · 풀기 · 컨테이너 3개 켜기 |
| `db` | 덤프 236MB, 적재 → API 응답까지 40초 |
| 비밀번호 | 없으면 401, 있으면 화면 · 선수 화면 · API 200, 없는 주소는 404 화면 |
| 검수 막기 | `/admin/review/` · `/api/v1/admin/...` 404 |
| 같은 응답 | 검색 「김도영」이 PC API와 같음 |
| 메모리 | 시즌 3개 무거운 API(`/batters` · `/pitchers` · `/home-runs` · `/leaders` …) 54번 + 선수 화면: Neo4j 약 990MB · API 71MB · Caddy 15MB = **약 1.1GB**. Neo4j 1.2GB · API 256MB로 묶어도 메모리 부족 종료 없음, 가장 느린 응답 0.53초 |

PC 개발 환경의 Neo4j가 1.9GB인 것은 힙 512MB · 트랜잭션 메모리 제한이 없기 때문이다. 서버 설정(힙 384MB · 캐시 256MB · 트랜잭션 128MB · 직접 메모리 128MB)으로 줄였다.
