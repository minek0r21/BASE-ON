## 3. 계산 규칙

### 3-1. 이닝

- 타석마다 `아웃 = post_outs − outs_when_up` (원천 열, 0~3). **결과가 없는 타석**(주루 아웃으로 이닝 종료, 3년 380타석)도 포함한다 — `build_pa`가 버리는 타석이라 투구 원본에서 따로 센다.
- 이닝 = 아웃 ÷ 3. 화면 표기는 `123⅓`·`45⅔` (아웃 수를 저장하고 표기는 프론트에서).
- 검증: 팀·경기당 아웃 합 평균 **26.6**, 91%가 24~27 (최소 12 강우 콜드, 최대 36 연장 12회).
- 한계: 타석 도중 투수가 바뀌면 그 타석의 아웃은 마지막 투수 몫이 된다(원천 `pitcher`가 타석 끝 투수). 공식 기록과 다를 수 있다 — 이닝 공식 기록 대조는 미완(10장).

### 3-2. 5지표

| key | 이름 | 수치 (`metric`) | 식 | 방향 |
| --- | --- | --- | --- | --- |
| `strikeout` | 탈삼진 | `k_pct` | 삼진 ÷ 상대 타자 | 높을수록 좋음 |
| `control` | 제구 | `bbhbp_pct` | (볼넷 + 사구) ÷ 상대 타자 | **낮을수록** 좋음 |
| `chase` | 유인 | `chase_pct` | 존 밖 공에 한 스윙 ÷ 존 밖 공 | 높을수록 좋음 |
| `hit_prevention` | 안타 억제 | `avg_against` | 피안타 ÷ 피타수 | **낮을수록** 좋음 |
| `power_prevention` | 장타 억제 | `iso_against` | 피장타율 − 피안타율 | **낮을수록** 좋음 |

- 상대 타자(`tbf`) = 결과가 있는 타석 수. 고의4구(공 없는 타석)도 1명.
- 화면 순서: 탈삼진 → 제구 → 유인 → 안타 억제 → 장타 억제 (투수가 혼자 정하는 것 → 수비·운이 섞이는 것 순).

### 3-3. 유인(체이스율)

- **존**: `|plate_x| ≤ 17/24 + 0.1208` ft, `sz_bot − 0.1208 ≤ plate_z ≤ sz_top + 0.1208` ft (홈플레이트 반폭 + 공 반지름, Statcast와 같은 판정). 공 일부라도 걸치면 존 안.
- **스윙**: `pitch_result` ∈ {`S` 헛스윙, `F` 파울, `H` 타격}. 번트 시도(`V`·`W`)와 희생번트 타석의 마지막 공은 분모·분자 둘 다에서 뺀다.
- 투구 위치가 없는 공(0.04~0.38%)은 뺀다. 리그 존 밖 비율 51.6%, 리그 체이스율 27.2%.
- 대상 투수의 존 밖 공은 최소 156개 — 대상이면 null이 생기지 않는다.

### 3-4. 대상 투수 값 범위 (2024~2026)

| | 탈삼진 | 제구 | 유인 | 안타 억제 | 장타 억제 |
| --- | --- | --- | --- | --- | --- |
| 중앙값 | 19.1% | 10.3% | 27.1% | .264 | .127 |
| 최소 | 7.2% | 2.2% | 18.6% | .102 | .029 |
| 최대 | 36.0% | 27.1% | 43.7% | .409 | .291 |

### 3-5. 백분위·등수

- 백분위 = 같은 시즌·같은 역할 대상 중 **나보다 나쁜 선수 수 ÷ n × 100** 반올림. 동률은 같은 값. 역방향 지표는 값이 클수록 나쁨.
- 등수 = 나보다 좋은 선수 수 + 1 (공동 순위). API에서 계산(타자 `axis_ranks`와 같은 방식).
- 1위 백분위: 선발(n 44~46) **98**, 불펜(n 83~92) **99**.

## 4. 왜 이 5개인가 (재계산)

대상 투수, 연속 두 시즌 모두 대상이고 역할이 같은 143쌍.

| 지표 | 해마다 유지 (피어슨 r) | 판단 |
| --- | --- | --- |
| 유인 | 0.64 | 투수 고유 능력, 가장 안정 |
| 탈삼진 | 0.61 | 〃 |
| 제구 | 0.58 | 〃 |
| 안타 억제 | 0.21 | 수비·운 영향 큼 → P2 |
| 장타 억제 | 0.11 | 〃 |
| (WHIP) | 0.15 | 안타 억제 + 제구와 겹치고 유지도 낮음 → 시즌 기록 숫자로만 |

축끼리 상관(스피어만): 제구↔유인 −0.55, 탈삼진↔안타 억제 −0.51, 탈삼진↔유인 0.38, 나머지 |r| ≤ 0.35. 다섯 축이 서로 다른 것을 보여 준다.

넣지 않은 후보: 직구 구속(능력의 재료이지 결과가 아님, 숫자로만 표시 — P8), 헛스윙률(탈삼진과 겹침), 꾸준함(투수는 월별 이닝이 적어 계산 불가가 많음), 평균자책점(자책점 구분 없음).

### 4-2. 다른 사이트·대안과 비교 (10-20)

| 사이트 | 투수 화면 | 비교 대상 |
| --- | --- | --- |
| Baseball Savant | 백분위 막대 13개: xERA · 직구 구속 · 직구 회전 · 커브 회전 · 평균 타구속도 · Chase% · Whiff% · K% · BB% · Barrel% · Hard-Hit% · GB% · Extension | 팀 경기당 1.25타석, 선발·불펜 섞음 |
| FanGraphs | 막대 없음. 요약 상자 K% · BB% · GB% · ERA · FIP · WAR, 구위는 Stuff+ 따로 | — |
| 스탯티즈 | 클래식·세이버 기록 표(ERA · WHIP · FIP · WAR)와 순위 | — |

원천에 타구속도·타구 종류·회전수·익스텐션·자책점이 없어 Savant는 5개만 재현했다(B: K% · BB% · Whiff% · Chase% · 직구 구속, 섞어서 비교). C는 K% · BB% · K−BB% · FIP · WHIP(나눠서 비교). 대상 투수·시즌 435개로 다섯 축 평균 백분위를 비교했다.

| | A (확정) | B Savant 재현 | C 결과 지표 |
| --- | --- | --- | --- |
| 그 시즌 RA9과 상관(크기) | **0.61** | 0.44 | 0.53 |
| 다음 시즌 RA9 예고 (157쌍) | 0.22 | **0.29** | 0.22 |
| 해마다 유지 | 0.46 | **0.62** | 0.41 |
| 약어 | 없음 | Whiff · Chase | FIP · WHIP · K−BB |

- A↔C 순위 상관 0.92: C는 A와 거의 같은 투수를 올리면서 약어만 늘어난다.
- B는 능력 예고가 낫지만 차이가 작고(0.29 대 0.22), 결과와 어긋나는 투수가 생긴다(베니지아노 2026: RA9 5.99인데 B 58점, A 21점). 입문 팬의 질문은 「지금 잘하나」라서 A로 정했다.
- 섞어서 비교하면 같은 A 지표로도 선발 +6.4점 · 불펜 −3.2점 치우친다 → P4 유지.
- 선수별 비교 화면: https://claude.ai/artifact/Vj62zGC6t9KR1vD2RVGERJ (비공개)

## 5. 데이터 모델 — `PitcherSeasonStat` 추가 속성

지금 속성(`g, gs, h, hr, bb, hbp, so, ab, avg, pitches, avg_velo`)에 더한다.

| 속성 | 뜻 |
| --- | --- |
| `tbf` | 상대 타자 |
| `outs` | 잡은 아웃 (이닝 = outs ÷ 3) |
| `b2`, `b3`, `sf`, `sh` | 피2루타·피3루타·희생플라이·희생번트 (피장타율 재료) |
| `slg` | 피장타율 |
| `whip` | (피안타 + 볼넷) ÷ 이닝 |
| `k_pct`, `bbhbp_pct`, `avg_against`(= 지금 `avg`), `iso_against`, `chase_pct` | 5지표 원 수치 |
| `o_pitches`, `o_swings` | 존 밖 공 · 그중 스윙 (체이스율 검산용) |
| `role` | `starter` / `reliever` |
| `team_id`, `team_games` | 주 소속팀 · 그 팀 경기 수 |
| `qualified` | 비교 대상 여부 |
| `pct_strikeout`, `pct_control`, `pct_chase`, `pct_hit_prevention`, `pct_power_prevention` | 백분위 (대상 밖이면 null) |

- `avg`는 이름을 바꾸지 않고 둔다(API-19·데모가 읽는다). `avg_against`는 응답에서만 쓰는 이름.
- 적재는 지금처럼 `02_load_season_stats.py`의 `MERGE … SET s += r.props`. 노드·관계는 새로 생기지 않는다.

## 6. API

### 6-1. API-02 `GET /players/{id}?season=` — 더하는 칸

값은 모양을 보이기 위한 예시다.

```json
{
  "primary_role": "pitcher",
  "pitching": {
    "role": "starter", "role_label": "선발",
    "g": 20, "gs": 20, "outs": 362, "tbf": 480,
    "h": 101, "hr": 9, "bb": 30, "hbp": 5, "so": 120,
    "avg": 0.231, "whip": 1.08, "avg_velo": 146.2,
    "qualified": true, "group_size": 46,
    "axes": [
      {"key": "strikeout", "label": "탈삼진", "metric": "k_pct", "value": 0.25,
       "percentile": 91, "rank": 5, "reverse": false},
      {"key": "control", "label": "제구", "metric": "bbhbp_pct", "value": 0.073,
       "percentile": 80, "rank": 10, "reverse": true}
    ],
    "not_qualified_message": null
  }
}
```

- `pitching`은 그 시즌 투구 기록이 없으면 null. 타자 칸(`stats`·`percentiles`…)은 지금 그대로.
- `axes`는 처음부터 설계 6-3 모양(고정 순서 배열)으로 낸다. 타자 쪽이 6-3으로 바뀌면 두 쪽이 같은 모양이 된다.
- `primary_role`: 그 시즌 상대 타자 수 > 타석 수이면 `pitcher`, 아니면 `batter`. 둘 다 없으면 null.
- 대상 밖: 백분위 칸 null, `not_qualified_message = "리그 비교 대상 아님(이닝 부족)"`.

### 6-2. API-19 `GET /players/{id}/seasons` — `pitching_seasons` 추가

시즌마다 `season, teams, role, g, gs, outs, tbf, h, hr, bb, hbp, so, avg, whip` (FR-05-04). 지금은 타자 기록이 없는 시즌을 건너뛰어 투수는 빈 목록이 된다.

### 6-3. 손대지 않는 것

API-01 검색(`position`으로 투수 구분 가능), API-17·06 맞대결(투수 방향은 Should, 다음), API-21 팀 투수 표(Should, 다음).
