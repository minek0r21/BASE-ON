# Neo4j 스키마 

노드 8개, 관계 14개다. 설계는 유사도 네트워크까지 한 번에 해 두고, 
적재는 1단계만 이후 시간이 남을시 2,3단계까지

| 단계 | 노드·관계 |
| --- | --- |
| 1단계 | 선수, 팀, 경기, 타석, 타자·투수 시즌 기록, 영상과 그 관계 |
| 2단계 | 구종(세부 유형), THROWS, VS_ARCHETYPE, LAST_PITCH |
| 3단계 | SIMILAR_TO (투수 유사도) |

## 전체 구조

```
(Player)-[:PLAYS_FOR {season, games, first_date, last_date}]->(Team)<-[:HOME|AWAY]-(Game)
(Player)-[:BATTED_IN]->(PlateAppearance)<-[:PITCHED_IN]-(Player)
(PlateAppearance)-[:PART_OF]->(Game)
(Player)-[:HAS_STAT]->(BatterSeasonStat)
(Player)-[:HAS_PITCHING_STAT]->(PitcherSeasonStat)
(Player)-[:HAS_POST_STAT]->(BatterPostseasonStat)
(Player)-[:HAS_POST_PITCHING_STAT]->(PitcherPostseasonStat)
(PlateAppearance)-[:CANDIDATE]->(VideoLink)
(PlateAppearance)-[:MATCHED_TO]->(VideoLink)

-- 2단계
(Player)-[:THROWS]->(PitchArchetype)
(Player)-[:VS_ARCHETYPE]->(PitchArchetype)
(PlateAppearance)-[:LAST_PITCH]->(PitchArchetype)

-- 3단계
(Player)-[:SIMILAR_TO]->(Player)
```

공 하나하나는 노드로 만들지 않는다. 타석에는 마지막 공 기준 값만 담고, 구종 비율·헛스윙률은 배치에서 요약해 관계 속성에 넣는다. 공 원본은 parquet에 남는다.

## 노드

### Player (선수)

타자와 투수를 같은 노드로 두고, 타자인지 투수인지는 타석노드에 관계로 연결할 때 BATTED_IN / PITCHED_IN 관계로 구분한다.

| 뜻 | 속성 | 타입 | 출처 | 만드는 방법 |
| --- | --- | --- | --- | --- |
| 선수 ID | player_id | 문자열 | `batter`, `pitcher` | 유일키 |
| 이름 | name | 문자열 | `batter_name`, `pitcher_name` | 가장 최근 경기의 이름 |
| 포지션 | position | 투수 / 포수 / 내야수 / 외야수, 없으면 null | 선수 프로필 CSV | `etl/05_load_profile.py` |
| 등번호 | back_number | 정수, 없으면 null | 선수 프로필 CSV | 39%는 빈칸 |
| 옛 이름 | former_names | 문자열 목록 (개명 4명, `etl/05_load_profile.py` FORMER_NAMES) | 설계.md 5-2 · statscene DEC-035 | 검색이 옛 이름도 찾는다 |
| 생년월일 | birth_date | 날짜 | 선수 프로필 CSV | |
| 투타 | bats_throws | 문자열 (예: 우투좌타) | 선수 프로필 CSV | 공식 표기. 예전 bats·throws(투구 데이터로 계산)는 10.11에 삭제 |

선수 프로필 CSV(`data/player_profile_view_cp949.csv`)는 2024~2026 선수 847명이다. 선수코드 = player_id이며, 원본 선수와 코드·이름이 100% 일치한다 (10.11 확인).

| --- | --- | --- | --- | --- |

| 팀 이름 | name | 문자열 | 직접 입력 | KIA, 두산, LG, 삼성, 롯데, SSG, 한화, 키움, KT, NC |

### Game (경기)

 game_pk는 `날짜 + 원정 + 홈 + 더블헤더 + 시즌` 형식이다(예: `20230401HHWO02023`). **포스트시즌은 앞 여덟 자리가 날짜가 아니다**(와일드카드 `4444`, 준PO `3333`, PO `5555` + 월일, 예: `33331017LGHT02026`) — 날짜·시즌은 game_pk에서 자르지 않는다(docs/포스트시즌.md 2장).

| 뜻 | 속성 | 타입 | 출처 | 만드는 방법 |
| --- | --- | --- | --- | --- |
| 경기 번호 | game_pk | 문자열 | `game_pk` | 유일키 |
| 날짜 | date | 날짜 | `game_date` |  |
| 시즌 | season | 정수 | `game_date` | 연도 |
| 더블헤더 순번 | dh_no | 정수 (0/1/2) | `game_pk` 13번째 글자 | 0 일반경기, 1·2 더블헤더 경기(하루에 두경기를 치룸) |
| 최종 점수 (홈, 원정) | home_final, away_final | 정수 | `post_home_score`, `post_away_score` | 경기 마지막 타석 마지막 공 기준 |
| 이닝 수 | innings | 정수 | `inning` | 경기의 마지막 이닝 (연장, 콜드 구분) |
| 경기 종류 | game_type | 문자열 | 파일 | `regular` 정규시즌 · `postseason` 포스트시즌 (`kbo_pbp_<시즌>_post.parquet`) |
| 포스트시즌 단계 | stage | 문자열, 정규시즌은 null | `round_code` | `WC` 와일드카드 · `SPO` 준PO · `PO` 플레이오프 · `KS` 한국시리즈 |
| n차전 | series_game_no | 정수, 정규시즌은 null | `series_game_no` | 그 시리즈의 몇 번째 경기 |

승패(W/L/D)는 어느 팀 입장인지에 따라 달라서 저장하지 않고 최종 점수로 계산한다.

### PlateAppearance (타석)

타석 id는 경기id+타석번호로 나타낸다
 at_bat_number는 경기 전체에서 1부터 이어진다. 

상황(situation)과 결과(events)는 마지막 공 줄에서 가져온다
(타석 도중 점수가 바뀌는 경우가 존재하기때문)

| 뜻 | 속성 | 출처·만드는 방법 |
| --- | --- | --- |
| 타석 ID | pa_id | `"game_pk_at_bat_number"`. 유일키 |
| 경기 번호 | game_pk | `game_pk` 그대로 |
| 경기 내 타석 번호 | at_bat_number | `at_bat_number` 그대로. 경기 전체에서 1부터 |
| 시즌 | season | `game_date`의 연도. 날짜 필터가 많아 경기 노드와 일부러 중복 저장 |
| 날짜 | date | `game_date` |
| 이닝 | inning | `inning` |
| 초/말 | inning_half | `inning_topbot` (top → 초, bot → 말) |
| 이 타자의 몇 번째 타석 | pa_no | 그 경기에서 이 타자의 몇 번째 타석 |
| 타석 결과 | events | 마지막 공의 `events`. 한글 표시는 API에서 변환 |
| 득점 | runs_scored | `runs_scored` |
| 시즌 몇 호 홈런 | hr_seq | 그 시즌 **정규시즌** 이 타자의 몇 번째 홈런. 홈런이 아니거나 포스트시즌이면 null |
| 포스트시즌 몇 호 홈런 | post_hr_seq | 그 해 포스트시즌 이 타자의 몇 번째 홈런(화면 「2026 포스트시즌 2호」). 정규시즌이면 null |
| 경기 종류 | game_type | 경기에서 복사 (`regular` · `postseason`) |
| 타석 전 점수 (홈, 원정) | home_score, away_score | 마지막 공의 점수 (결과 직전) |
| 타석 후 점수 (홈, 원정) | post_home_score, post_away_score | 마지막 공의 타석 후 점수 |
| 상황 | situation | 없음 / 동점 / 리드 / 역전 / 끝내기 (공격팀 기준). 영상 매칭용 |
| 1·2·3루 주자 | on_1b, on_2b, on_3b | 주자가 있으면 참 |
| 투구 수 | pitch_count | 그 타석의 공 개수 |
| 최종 볼카운트 | final_balls, final_strikes | 마지막 공의 `balls`, `strikes` |
| 아웃 수 | outs_when_up | 그 타석 때 아웃 수 (마지막 공의 `outs_when_up`, 썸네일 중계 표시) |
| 영상에 없음 | no_video · no_video_by · no_video_at | 검수에서 「이 홈런은 영상에 없음」으로 표시 (수동 표시 큐에서 빠진다) |
| 마지막 공 구종 코드 | last_pitch_type | 마지막 공의 `pitch_type` |
| 마지막 공 구종 이름 | last_pitch_name | 마지막 공의 `_naver_pitch_name` (싱커 → 투심 통일) |
| 마지막 공 구속 | last_pitch_speed | 마지막 공의 `release_speed_kmh` |

### BatterSeasonStat (시즌 기록)

타자 한 명의 한 시즌이 노드 하나다. 트레이드된 선수도 하나의 노드만

(계산가능하고 쓰일 가능성있는 데이터는 전부 넣어봤습니다)

| 뜻 | 속성 | 계산 |
| --- | --- | --- |
| 시즌 기록 ID | stat_id | `"선수ID_시즌"`. 유일키 |
| 시즌 | season |  |
| 타석 | pa | 타석 수 |
| 타수 | ab | pa − (bb + hbp + sf + sh + 타격방해) |
| 안타 | h | single, double, triple, home_run |
| 2루타, 3루타, 홈런 | b2, b3, hr | double, triple, home_run |
| 볼넷, 사구, 삼진 | bb, hbp, so | walk, hit_by_pitch, strikeout |
| 희생플라이, 희생번트 | sf, sh | sac_fly, sac_bunt |
| 타율 | avg | h ÷ ab |
| 출루율 | obp | (h + bb + hbp) ÷ (ab + bb + hbp + sf) |
| 장타율 | slg | (h + b2 + 2×b3 + 3×hr) ÷ ab |
| OPS | ops | obp + slg |
| 볼넷 비율 | bb_pct | bb ÷ pa |
| 삼진 비율 | k_pct | so ÷ pa |
| 순수 장타력 | iso | slg − avg |
| 월별 OPS 표준편차(꾸준함계산에쓰임) | ops_sd | 30타석 이상인 달의 월별 OPS 표준편차. 그런 달이 3개 미만이면 null |
| 삼진회피 백분위 | pct_contact | k_pct 기준, 낮을수록 높음. 0~100 |
| 안타생산 백분위 | pct_hit | avg 기준 |
| 파워 백분위 | pct_power | iso 기준 |
| 선구안 백분위 | pct_eye | bb_pct 기준 |
| 꾸준함 백분위 | pct_consistency | ops_sd 기준, 낮을수록 높음 |
| 백분위 대상 (규정타석 50% 이상) | qualified | 팀 경기 수 × 3.1 의 50%이상이면 참. 트레이드된 선수는 그 시즌 타석이 가장 많은 팀의 경기 수 기준 |

백분위는 같은 시즌 규정타석의 50% 이상인 타자(2025 기준 223타석 이상) 중 몇 %를 앞서는지다. 대상이 아닌 타자는 백분위를 null로 두고 화면에 표시하지 않는다. 화면의 "상위 n%"는 100 − 백분위다. 진행 중인 시즌은 그때까지의 팀 경기 수로 기준을 잡는다.

### BatterPostseasonStat · PitcherPostseasonStat (포스트시즌 기록)

선수 한 명의 한 해 포스트시즌이 노드 하나(`stat_id` = `<선수>_<시즌>_post`). 정규시즌 기록과 따로 집계하고 **백분위 · 비교 대상 · 꾸준함이 없다**(docs/포스트시즌.md PS1).

- 타자 `(Player)-[:HAS_POST_STAT]->(BatterPostseasonStat)`: games · pa · ab · h · b2 · b3 · hr · bb · hbp · so · sf · sh · avg · obp · slg · ops
- 투수 `(Player)-[:HAS_POST_PITCHING_STAT]->(PitcherPostseasonStat)`: g · gs · tbf · outs · r(책임 주자 기준) · h · b2 · b3 · hr · bb · hbp · so · sf · sh · ab · avg · slg · whip

`BatterSeasonStat` · `PitcherSeasonStat` · `Outing`은 정규시즌만으로 계산한다(`Outing`은 포스트시즌 등판도 만들고 `game_type`으로 나눈다).

### PitchArchetype (구종 세부 유형) · 2단계

시즌별로 구종마다 구속·무브먼트·릴리스 높이로 군집화한다. 좌투는 `ax` 부호를 뒤집어 좌우투가 같은 유형에 들어간다. 
너클볼·슬러브처럼 공이 적은 구종은 나누지 않는다. PitchType 노드는 두지 않고 속성으로 대신한다.

| 뜻 | 속성 | 예시 | 만드는 방법 |
| --- | --- | --- | --- |
| 세부 유형 ID | archetype_id | `2025_SL_1` | `시즌_구종코드_번호`. 유일키 |
| 시즌 | season | 2025 |  |
| 구종 코드 | pitch_type | SL | `pitch_type` |
| 구종 이름 | pitch_name | 슬라이더 | `_naver_pitch_name` |
| 유형 이름 | label | 고속 슬라이더 | 구종 평균과 비교해 자동 생성, 수정 가능 |
| 평균 구속 | avg_velo | 134.9 | 군집 평균 `release_speed_kmh` |
| 평균 수평 무브먼트 | avg_h_break | 0.3 | 군집 평균 `ax` (좌투는 부호 반전) |
| 평균 수직 무브먼트 | avg_v_break | −25.7 | 군집 평균 `az` |
| 평균 릴리스 높이 | avg_release_z | 5.8 | 군집 평균 `release_pos_z` |
| 공 수 | n_pitches | 59405 | 이 유형으로 분류된 공 개수 |
| 투수 수 | n_pitchers | 371 | 이 유형을 던진 투수 수 |

## 관계

- ()는 노드 [: ]는 관계
- 2단계는 구종 세부 유형 관계(투수의 구종 구성, 타자의 구종별 성적), 3단계는 투수 유사도 관계입니다 

| 단계 | 관계 | 설명 | 속성 |
| --- | --- | --- | --- |
| 1 | (Player)-[:PLAYS_FOR]->(Team) | 선수가 그 시즌에 뛴 팀. 시즌 중 트레이드되면 2개. 최근 팀은 last_date가 가장 늦은 관계 | season, games(그 팀에서 뛴 경기 수), first_date, last_date(첫·마지막 출전일) |
| 1 | (Game)-[:HOME]->(Team), (Game)-[:AWAY]->(Team) | 경기의 홈팀과 원정팀 |  |
| 1 | (Player)-[:BATTED_IN]->(PlateAppearance) | 이 선수가 이 타석의 타자였음 |  |
| 1 | (Player)-[:PITCHED_IN]->(PlateAppearance) | 이 선수가 이 타석의 투수였음 |  |
| 1 | (PlateAppearance)-[:PART_OF]->(Game) | 이 타석이 어느 경기의 타석인지 |  |

## 적재 규칙

- 적재 범위는 2024~2026.7.26이다 (2023은 쓰지 않음). 프로토타입은 2025만 적재.
- 구종 이름의 싱커는 투심으로 통일한다.
- 결과(`events`)가 빈 타석 380개는 제외한다.
- 대타가 타석 도중 바뀐 51건은 마지막 공의 타자로 기록한다.
- 52경기는 at_bat_number 중간이 비어 있다(원본 누락). pa_no는 순서대로 매긴다.
- 헛스윙은 `pitch_result`의 S, 스윙은 S·F·W·H로 센다. T는 루킹 스트라이크, B는 볼이다. V(508개)는 뜻이 확실하지 않아 제외한다(확인 필요). 이 규칙은 2단계 헛스윙률 계산에 쓴다.

## 검색·필터 인덱스

유일키 제약조건은 자동으로 인덱스가 생긴다. 아래 5개는 자주 쓰는 검색·필터를 빠르게 하려고 따로 만든다.

| 인덱스 | 대상 | 쓰는 곳 |
| --- | --- | --- |
| player_name (TEXT) | Player.name | 선수 검색 (API 1) |
| pa_season | PlateAppearance.season | 시즌별 타석 조회 |
| pa_date | PlateAppearance.date | 경기 기록, 영상 매칭 날짜 필터 |
| batter_stat_season | BatterSeasonStat.season | 시즌 기록·백분위 조회 |
| matched_status | MATCHED_TO.status (관계) | 검수 목록 (API 7, 10) |

```cypher
CREATE TEXT INDEX player_name IF NOT EXISTS FOR (n:Player) ON (n.name);
CREATE INDEX pa_season IF NOT EXISTS FOR (n:PlateAppearance) ON (n.season);
CREATE INDEX pa_date IF NOT EXISTS FOR (n:PlateAppearance) ON (n.date);
CREATE INDEX batter_stat_season IF NOT EXISTS FOR (n:BatterSeasonStat) ON (n.season);
CREATE INDEX matched_status IF NOT EXISTS FOR ()-[r:MATCHED_TO]-() ON (r.status);
```
